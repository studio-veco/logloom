# LOGLOOM

会議の音を聞きながら、その場でマインドマップが育っていきます。終点には、その論点で
何が話されたかをまとめた文章が出ます。

```
マイク（自分）      ─ ffmpeg   ┐
                              ├ 黙った所で切る ─ whisper-server ─ 校正辞書 ─ Jev ─ 木 ─ drawio
この Mac の音（相手）─ syscap  ┘
```

## 支度

```bash
node logloom/tools/setup.mjs
```

足りないものだけ取ってきます（drawio 約155MB、聞き取りのモデル 約1.6GB、会議の音を拾う係）。
どれも大きいので、リポジトリには入れていません。

手元に要るもの。`brew install ffmpeg whisper-cpp` で入ります。

| 要るもの | 何に | 無いとどうなるか |
| --- | --- | --- |
| Node 20 以上 | 本体 | 動きません |
| ffmpeg | マイクの音を取り込む | 聞き取れません |
| whisper.cpp | 聞き取り | 聞き取れません |
| swiftc（macOS） | 会議の音を拾う係を組む | Meet・Zoom の相手の声が拾えません |
| 手元の `claude` か `codex` | 見出しと要約 | 発言の言葉から作ります |
| Jev の鍵 | 枝分け・決定/やること/課題の印 | 枝を発言6件ごとに切ります |
| 校正の道具（任意） | 誤字の辞書 | 辞書なしで動きます |

## 起動

```bash
node logloom/server.mjs 8580
```

`.claude/launch.json` に `logloom`（ポート 8580）として登録してあります。

## 鍵の置き場所

**この道具は鍵を持ちません。使う人の鍵で動きます。**

- **Jev**：画面の「ほかの操作 → Jev の鍵を入れる」から貼ると、通ることを確かめてから
  `.env` に保存します（600・`.gitignore` 済み）。環境変数 `TYPESAFE_API_KEY` でも、
  `LOGLOOM_SECRETS` が指すファイルからでも読みます。鍵そのものは画面に返しません（末尾4文字だけ）。

  **すでに鍵が決まっている機械では、画面から入れ替えられません。**
  環境変数などに置いてあるということは、その機械ではその鍵を使うと決めてあるということなので、
  押し間違いで変わらないように閉じてあります。
  持っていった先には鍵が無いので、そのまま入力できます。
  自分の機械でも入れ替えたいときは `LOGLOOM_KEY_UNLOCK=1` を立ててください。
- **Claude / Codex**：手元の `claude -p` か `codex exec` を呼ぶだけで、鍵は要りません。
  どちらも利用者自身の契約で動きます。画面の「ほかの操作 → 書かせる係」で切り替えます。
  **Codex を選ぶと、議題ごとに絵を作らせられます。**Codex に入っている `imagegen` の係が
  `image_gen` の道具を使うので、**`OPENAI_API_KEY` は要りません**（ChatGPT のログインで動きます）。
  透明な背景に白一色のピクトグラムを1枚作らせ、96px に縮めてから地図に埋めます。
  縮めるのは、1024px のままだと1枚 650KB あり、議題が増えるたびに drawio へ渡すものが
  膨らむからです。埋めたあとは data URI なので、**書き出した `.drawio` を他所で開いても絵が残ります**。
  1枚あたり60〜90秒かかるので、待たずに先へ進み、できたところで地図に出します。
- **校正の道具**：`LOGLOOM_GLOSSARY` で場所を指せます。指さなければ logloom の隣を探します。

## 使うもの

| 何に | 何を | どこから |
| --- | --- | --- |
| 地図 | drawio | `vendor/drawio`（jgraph/drawio v31.4.6 の公式ビルドを展開。手元から出しているので外へ出ません） |
| 聞き取り | whisper.cpp | `whisper-server`（常駐）と `whisper-cli`（録ってあるファイル用） |
| 誤字 | 共通辞書（約6,700語） | 手元の校正の道具を直に読み込む。写さない。`LOGLOOM_GLOSSARY` で場所を指せます |
| 枝分け・印 | Jev（TypeSafe System One） | `TYPESAFE_API_KEY`（画面から入れるか、環境変数） |
| 見出し・要約 | 手元の `claude -p` か `codex exec` | どちらも利用者自身の契約で動く。こちらの鍵を埋め込まない |
| 議題の絵 | Codex の `image_gen` | ChatGPT のログインだけで動く。API キーは要らない |

モデルは `~/.cache/whisper-models/ggml-large-v3-turbo.bin`。
`LOGLOOM_WHISPER_MODEL` で差し替えられます。

## 誤字をなくす道すじ

**入口が先です。** whisper の初期プロンプトに 校正辞書から作った語彙を渡します。
出口で置換するより確実に効きます（実測：語彙を渡しただけで「生成愛」が「生成AI」、
「施策」が「試作」で出るようになりました）。

そこを抜けたぶんに、出口で3枚の受け皿を当てます。

1. **辞書の正誤表**（`report.applyGlossary`）。載っている誤りだけを直します。
   語の内側には食い込みません（「お茶の水女子大学学」にならない）。
2. **会議の中で読みが近い語**（`terms.suspects`）。同じ会議にもっと多く出ている語を探します。
3. **辞書の語と読みを直に比べる**（`lib/yomimatch.mjs`）。会議が始まったばかりで
   比べる相手が居ないときの道です。大文字の略語は字名に開いてから比べます
   （「せいせいAI」のままだと「せいせいあい」と離れて、「生成愛」を取り逃がします）。

2 と 3 は**直しません。候補を出すだけ**で、当たり外れは Jev が決めます（0.8 以上で直す）。
直したところは書き起こしの欄に残ります。

## Google Meet と Zoom（記録用の参加者を入れない）

会議に記録用の参加者を足すやり方は使いません。相手の画面には何も出ません。
**この Mac が耳で聞いている音を、そのまま拾います。**

- **相手の声** … macOS の ScreenCaptureKit（`native/syscap.swift`）。画面収録の仕組みですが、
  音だけを取り出します。BlackHole のような別の音の入口を入れなくて済みます。
- **自分の声** … マイク（ffmpeg）。
- 書き起こしには、どちらから入った声かを「自分」「相手」として残します。

初回に **macOS の「画面収録」の許可**が要ります。許可を出す相手は、このサーバを起こした親
（ターミナル、または Claude のアプリ）です。許可が無いときは画面にそう出て、
設定を開くボタンが出ます。**こちらからは許可を出せません。本人が出すものです。**

スピーカーで会議をしていると、相手の声はこの Mac の音としても、マイクに回り込んだ音としても
入ってきます。**同じ発言が20秒の内に両方から入ったら、1つにまとめます**（残すのは
会議の音のほう。マイクに回り込んだ音より綴りが崩れていません）。イヤホンなら起きません。

`native/syscap.swift` は要るときに1度だけ `swiftc` で組み、`~/.cache/logloom/syscap` に置きます。

## この会議の語

人名・社名・商品名は辞書にありません。画面の「この会議の語を足す」に入れておくと、
聞き取りの語彙の**先頭**に入り、読みの照合にも効きます。

**出口では直しようがない種類の誤りがあります。**「設計案」が「設定案」と書かれても、
どちらもふつうの語なので、読みを比べても決まりません。実測では、語彙に「設計案」を
入れただけで正しく書かれるようになりました。始める前に入れるほど効きます。

## 手で直す

**聞き取りと辞書と Jev を通しても、残る誤りはあります。**「3小間」が「3個まで」と
書かれるように、音がそのまま重なっているものは、読みを比べても決まりません。
書き起こしの各行の「直す」から、人が直せます。

直すと、4つが同時に動きます。

1. その発言の文を入れ替えます。
2. **同じ誤りが入っているほかの発言も直します**（「同じ誤りも直す」を外すと、その行だけ）。
3. **直した語を覚えて、これから来る発言にも当てます**。あわせて、聞き取りの語彙にも
   足します。出口で直すだけでは、次も同じように聞こえるためです。
4. **その論点の見出しと要約を作り直します。**ここを飛ばすと、書き起こしだけ直って
   マインドマップが古い文のまま残ります。決まったこと・やること・課題の印も付け直します。

覚えるのは**短い語の入れ替えだけ**です。文をまるごと書き直したときは覚えません
（二度と当たらないものが正誤表に溜まるだけになります）。

要約や見出しを作っている最中に直しても捨てません。作り終わってから、もう一度作り直します。

## 枝の分け方

発言ごとに、Jev へまとめて1回だけ問います。

1. いまの論点の続きか（0.45 以上なら続き）
2. 前に出た論点へ戻ったか（0.62 以上。戻りは新設より強い証拠が要ります）
3. どの議題の中の話か（0.50 以上。**いまの議題だけでなく前の議題も見ます**）
4. 中身のある発言か（0.40 未満なら枝を生やさず、いまの枝に付けます）

4 は必ず最後です。先に置いたとき、「次に、ウェブサイトのリニューアルについてです」を
進行の合図と見なして展示会の論点に混ぜ、ウェブサイトの話がまるごと展示会の下に
ぶら下がりました。話題の名を告げる発言は、枝を分けるための一番強い手がかりです。

決まったこと・やること・残った課題の印も Jev が付けます。**一番強い1つだけ**を取ります。
3つとも付けていたとき、同じ文が3つの箱に並んで地図が読めなくなりました。

要約は「発言が3つ貯まったとき」と「次の話題に移ったとき」に作り直します。それだけだと
**会議の終わりの論点にだけ要約が付きません**（次の話題に移らないため）。45秒黙ったとき、
聞き取りを止めたとき、メニューの「まだ要約の無い論点をまとめる」で、まとめて作ります。

## 空耳をはじく

whisper は**無音に近い音に当てると、すらすらした嘘を返します。**実測で出たもの：

- 「ご視聴ありがとうございました」（静かな部屋の3秒）
- 「アジア大会競泳男子400m個人メドレーで…」（会議と何の関係もない一文）

決まり文句の一覧だけでは足りないので、3つで見ます。

1. **決まり文句の一覧**（`GHOST`）
2. **日本語らしさ**（`verbose_json` の `language_probabilities`）。実測で、本物の日本語は
   0.999、無音の空耳は 0.050。`avg_logprob` も本物 -0.03／空耳 -0.377 と離れています。
3. **音の大きさ**。いちばん大きかった所と、発言を通しての平均の両方を、静かなときの
   大きさと比べます。片方だけだと、物音1つで越えてしまいます。

静かなときの大きさには下限（0.0015）を置いています。置かずにいたとき 0.0004 と読み、
敷居が部屋の雑音より下がって、上の空耳を通しました。

## Jev や Claude が無いとき

止まりません。そう書いて出します。

- **書き起こしは、どちらが無くても最後まで動きます。**音を文字にするのは whisper、
  誤字は 校正辞書で、Claude も Jev も通りません。
- Jev の鍵が無い → 枝は発言6件ごとに切ります。画面の札に「枝は発言数で切ります」と出ます。
- `claude` が使えない、または画面の切り替えを切った → 見出しと要約を `lib/youyaku.mjs` が
  **発言の言葉だけ**で作ります。見出しはその論点でいちばん多く出ている語、要約は
  中身の濃い発言を2文つないだもの。言葉を足さないので硬くなりますが、嘘は書きません。
  終点の箱にも「発言の言葉から」と出ます。

## 画面

デジタル庁デザインシステム（β版 v2.18.0）に合わせています。色は公式のデザイントークン
`@digital-go-jp/design-tokens` v2.0.1 の値をそのまま使い、ボタンの角丸・太さ・フォーカスの
二重枠（Yellow-300 と黒）は本体のページで実測して合わせました。

**アイコンは必ずラベルと並べます。**アイコンだけ・色だけで意味を伝えません
（デザインシステムのアクセシビリティの決めごと）。状態の札（チップラベル）も同じで、
必ず字で状態を書きます。

操作は次のとおりです。

- 聞き取りを始める／止める（音の入口はマイクのほか ZoomAudioDevice なども選べます）
- 「会議の音も」に印を付けると、Meet や Zoom の相手の声も拾います
- 文字を貼って試す（マイクが無くても枝分けと要約を確かめられます）
- 録ってある音を流し込む（m4a・mp3・mp4・wav）。**生のときと同じように黙ったところで切ってから**
  聞き取ります。丸ごと1回で投げると初期プロンプトが先頭30秒までしか効かず、45秒の会議で
  「設計案→設定案」「来月中→3月中」になり、1文まるごと落ちました。切れ目が見つからない音だけ
  `whisper-cli` で丸ごと聞き取ります
- 書き出し（`.drawio` と議事録の `.md`）
- drawio で開いて整える（手で並べ替えて、PNG・SVG・PDF などに書き出せます）

## スマホから見る

同じ Wi-Fi の中から開けます。**Mac が聞き取って、スマホは画面として見るだけ**です。

```bash
node logloom/server.mjs 8580 --lan
```

`--lan` を付けたときだけ口を開けます（既定はこの機械の中だけ）。開けている間は画面の札に
「同じ Wi-Fi に公開中」と出ます。**会議の中身が同じ Wi-Fi の誰からも見えます。**
要らなくなったら `--lan` を外してください。

画面は 375px でも横にはみ出しません（帯は1段、マインドマップは畳んで画面いっぱいにできます）。

## スマホのアプリにはできるか

**会議の相手の声を拾う部分は、iPhone でも Android でもできません。**両方の OS が、
まさにこの用途を塞いでいます。

- **Android**：`AudioPlaybackCapture` が拾えるのは `USAGE_MEDIA` `USAGE_GAME` `USAGE_UNKNOWN` の
  3つだけです。通話に使う `USAGE_VOICE_COMMUNICATION` は、どう設定しても拾えません。
  Zoom も Meet も通話はこれを使います。
- **iOS**：ReplayKit の `audioApp` で取れるのは、配信しているアプリ自身の音とマイクだけです。
  ほかのアプリの音は取れません（AVPlayer・Safari・ミュージックの音すら取れない、と書かれています）。

マイクで部屋の声を録るだけなら、スマホのアプリにできます。ただし whisper の
large-v3-turbo は 1.6GB あるので、スマホでは small か base に落とすことになり、
聞き取りの質は落ちます。校正辞書の読み合わせは Python（janome）に頼っているので、
そこも作り直しが要ります。

## 気をつけるところ

- **マイクの許可**は、このサーバを起こした親（ターミナルや Claude のアプリ）に付きます。
  はじめて「聞き取りを始める」を押したとき、macOS が親の名前で尋ねます。
- `claude -p` を起こすとき、`ANTHROPIC_BASE_URL` と `ANTHROPIC_API_KEY` を環境から消しています。
  Claude Code の中からこのサーバを起こすと、これらが親の中継を指していて、子の claude が
  そこへ繋ぎにいって落ちます（見出しも要約も1件も書けませんでした）。
- whisper のモデルは 1.6GB あります。最初の「聞き取りを始める」で読み込むので、
  1分ほどかかります。2回目からはすぐです。
- WAV から音を取り出すとき、**44バイト決め打ちにしていません。** ffmpeg は LIST チャンクを
  足すことがあり（実測では音は78バイト目から始まっていました）、34バイトずれると
  16ビットの上下が入れ替わって、切れ目も聞き取りも崩れます。`data` の位置を読んで切ります。
